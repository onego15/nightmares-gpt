# 検証記録

検証日：2026-10-20（日本時間）。
環境：Windows、Node.js v22.17.0、Python 3.10、Pillow 12.0.0、Codex内蔵ブラウザ。
実際に `http://127.0.0.1:4187/` を開き、キーボードと画面のボタンを操作した。

## 通しプレイ

| 場面 | 実施内容 | 結果 |
| --- | --- | --- |
| タイトル | 起動、画面構成、開始 | 正常 |
| 受付 | 移動、ヒューズ取得、配電盤、扉 | 第二幕へ到達 |
| 客席 | 記録を読む、灯から点けて誤答、雨→灯→月 | 誤答時リセット、正答時解錠 |
| 舞台裏 | 再読み込み、つづきから、記録の探索、錘2・4・1 | 保存復帰、第四幕へ到達 |
| 追跡 | Shiftで走る、Spaceで跳ぶ、つまずき、非常灯 | 追跡を脱出 |
| 最終幕 | 楽譜、照明2・1・3、終演の鐘、右端の出口 | 終幕画面に到達 |
| 証跡 | 終幕のスクリーンショット | `docs/ending.png` |
| ブラウザログ | 通しプレイ終了後のerror / warn取得 | 取得結果は空 |

幕のカードが表示される間は操作を待ち、カメラ演出の間は移動をロックしている。
画像・DOMの両方で状態を確認した。内部状態を書き換えて通しプレイを完了させてはいない。
第三幕と第四幕で保存復帰を検証したため、完全な連続一発プレイという意味での計時はしていない。

## 確認後の調整

- 受付の配電盤を使ったあと、インベントリ表示が更新されるよう修正。
- 次の幕へ移った際に前の字幕が残らないよう修正。
- 月を吊り上げる動きと最終幕の幕の開きに補間を追加。
- 第四幕で最初に移動するまでは追跡が始まらないよう変更。
- 追跡者が画面外へ遠ざかりすぎたため、追跡速度を278に調整。
- 調整後の第四幕は `?qa` の「QA：追跡の再検証」から独立して再プレイ。
  約6秒走った時点で人物・追跡者・先の通路が同時に見えることをスクリーンショットで確認。
  そのまま非常灯まで進み、追跡完了の字幕を確認。
- `?qa` は局所的な再検証用の入口。通常URLには検証ボタンを表示しない。

## 自動検査

`npm test`：4件成功、失敗0。

1. 正しい集合でも順番が違えば照明の解答にしない。
2. 錘と集光を別の解答として検証する。
3. ジャンプ高度と横位置による障害物判定。
4. 壊れたデータや範囲外の幕番号をセーブとして読み込まない。

`node --check game.js`：成功。
当初 `node --test` は制約下の子プロセス起動が `EPERM` となったため、
同じ `node:test` のテストを `node tests/rules.test.js` として単一プロセスで実行する構成に変更。
